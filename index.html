How I work

Five working rules

  • discovery

    Design before ticketsEvery requirement maps to a design before it enters a sprint.

  • architecture

    Business logic stays in the coreRating, policy, payments and claims logic lives in the core APIs, never in the portal layer.

  • priority

    Prioritise in the openWSJF and MoSCoW, with INVEST stories and testable acceptance criteria.

  • users

    Validate with real usersAt least two client-led usability sessions a month, and UX sign-off before development starts.

  • release

    Release on evidenceTicket-by-ticket QA, then customers run the same UAT scripts for independent sign-off. UAT pass scores stay above 90%.
